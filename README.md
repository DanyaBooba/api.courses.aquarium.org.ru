# api.courses.aquarium.org.ru

API для сайта курсов [courses.dybka.ru](https://courses.dybka.ru): каталог и содержимое курсов, вход по коду из письма, панель управления для авторов и загрузка картинок.

Стек: Node.js 20+, Express 5, MySQL (mysql2), JWT, Nodemailer, sharp.

## Запуск

```bash
npm install
cp .env.example .env    # заполнить TOKEN_SECRET и базу
mysql -u root courses < database/schema.sql
npm run dev             # node --watch server.js
```

Без `TOKEN_SECRET` сервер не стартует. Проверка, что он поднялся: `GET /health` → `{ "status": "ok" }`.

`npm start` запускает `nodemon server.js`, но nodemon нет в зависимостях: его нужно поставить глобально или запускать сервер через `node server.js` / менеджер процессов.

### Обновление базы

Для уже работающей базы изменения схемы лежат в `database/migrations/` — их применяют по порядку, один раз:

```bash
mysql -u root courses < database/migrations/001-course-review.sql   # модерация курсов
mysql -u root courses < database/migrations/002-course-stats.sql    # просмотры и читатели
```

В `schema.sql` они уже учтены: новой базе миграции не нужны.

### Перенос курсов из файлов сайта

`database/seed-courses.sql` переносит курсы из `src/data/courses/*.js` сайта в таблицу `courses`. Перед запуском администратор должен хотя бы раз войти на сайт: он становится владельцем курсов. Курсы добавляются закрытыми; повторный запуск перезаписывает содержимое, но не трогает признак «закрыт».

## Как устроено

```
server.js            — читает .env и запускает приложение
app.js               — Express: helmet, CORS, раздача /uploads, маршруты, обработка ошибок
routes/              — какие адреса есть и какие проверки перед ними
controllers/         — обработка запросов
models/              — запросы к MySQL
services/            — JWT, коды входа, письма, проверка курса
middlewares/         — вход, уровень доступа, 404, ошибки
templates-email/     — HTML-письма
config/              — база и уровни доступа

```

Все ответы — JSON. Ответы API не кэшируются (`Cache-Control: no-store`), кроме картинок из `/uploads`: их имена уникальны, поэтому они кэшируются на год.

### Вход

Паролей нет. Пользователь вводит почту, получает на неё код из 6 символов и обменивает его на токен.

1. `POST /auth/code` — сервер создаёт код, хранит в базе только его HMAC-хэш и отправляет код письмом. Новый запрос отменяет прежний код.
2. `POST /auth/verify` — код проверяется; на 5-й неверной попытке он сгорает. При первом входе создаётся пользователь.
3. Дальше токен передаётся в заголовке `Authorization: Bearer <token>`.

На оба адреса стоит ограничение: не больше 20 запросов за 15 минут с одного IP.

### Уровни доступа

| Уровень | `access` | Что может |
|---|---|---|
| Ждёт подтверждения | `0` | Войти и читать открытые курсы |
| Автор | `1` | Создавать курсы, править и удалять свои, загружать картинки; скрывать свои курсы, но не публиковать — только отправлять на проверку |
| Администратор | `100` | Всё, что автор, но с любыми курсами; публиковать курсы; управлять пользователями |

### Модерация курсов

Курс автора всегда создаётся скрытым. Опубликовать его (`disabled: false` в `PUT`) может только администратор — автору сервер ответит `403`. Автор отправляет курс на проверку (`POST /courses/:id/review`), и администраторам — из `ADMIN_EMAILS` и с уровнем `100` в базе — приходит письмо. Администратор публикует курс обычным `PUT` — заявка снимается, автору уходит письмо «Курс опубликован». Или возвращает на доработку (`DELETE /courses/:id/review` с причиной) — автору уходит письмо с ней. Скрыть свой курс автор может в любой момент; открыть снова — опять через проверку.

Новый пользователь получает уровень `0`, а администраторам уходит письмо. Почты из `ADMIN_EMAILS` при первом входе сразу получают уровень `100`. Когда администратор повышает пользователя с `0`, тому приходит письмо «Доступ открыт».

## Маршруты

Обозначения: 🔓 — без входа, 🔑 — нужен токен, ✏️ — автор и выше, 👑 — администратор.

### Служебное

#### `GET /health` 🔓

`200 { "status": "ok" }`

#### `GET /sitemap.xml` 🔓

Карта сайта для поисковиков: главная, открытые курсы с уроками, правовые страницы. Собирается из базы на каждый запрос, поэтому новые курсы и уроки попадают в неё сразу. Закрытые курсы (`disabled`) не попадают. Адреса строятся от `APP_URL`, `lastmod` — дата последней правки курса. Кэшируется на час.

На неё ссылается `robots.txt` сайта.

### Вход

#### `POST /auth/code` 🔓

Отправляет код на почту.

```json
{ "email": "user@example.com" }
```

- `200 {}` — письмо отправлено
- `400` — некорректная почта
- `429` — слишком много запросов
- `502` — письмо не ушло

#### `POST /auth/verify` 🔓

Обменивает код на токен. Регистр, пробелы и дефисы в коде не важны.

```json
{ "email": "user@example.com", "code": "AB3-K7M" }
```

- `200 { "token": "…", "user": User }`
- `400` — неверный код или код устарел
- `429` — исчерпаны попытки, нужен новый код

### Профиль

#### `GET /profile` 🔑

`200 { "user": User }`

#### `PATCH /profile` 🔑

Меняет имя (до 120 символов).

```json
{ "name": "Даниил" }
```

`200 { "user": User }`

#### `GET /profile/courses` 🔑

Курсы, которые создал пользователь. `200 { "courses": [CourseShort] }`

### Курсы

#### `GET /courses` 🔓 (токен необязателен)

Каталог: все курсы, в том числе закрытые, без содержимого уроков. Порядок — по дате создания. Курсы на проверке (`reviewRequestedAt`) видят только их автор и администратор — остальным они не отдаются.

`200 { "courses": [CourseShort] }`

#### `GET /courses/:id` 🔓 (токен необязателен)

Курс целиком.

- `200 { "course": Course }`
- `403 { "status": "wip" }` — курс закрыт (`disabled`), а запрашивает не автор и не администратор
- `404` — курса нет, или он на проверке, а запрашивает не автор и не администратор

#### `POST /courses/:id/view` 🔓 (токен необязателен)

Сайт сообщает, что читатель открыл курс. `visitorId` — анонимный UUID, который браузер хранит у себя: по нему считаются разные читатели.

```json
{ "visitorId": "0f8fad5b-d9cb-469f-a165-70867728950e" }
```

Каждый запрос прибавляет к `views` единицу, а к `readers` — только если этот `visitorId` пришёл на курс впервые. Автор курса и администратор (с токеном) статистику не накручивают. Не больше 300 запросов за 15 минут с одного IP.

- `204` — засчитано
- `400` — некорректный `visitorId`; `404` — курса нет или он закрыт; `429`

#### `POST /courses` ✏️

Создаёт курс. Тело — курс (см. [Курс](#курс)), `id` обязателен. Если `author` не передан, подставляются имя и почта пользователя.

- `201 { "course": Course }`
- `400` — ошибка в полях, в `message` сказано, в каком
- `409` — адрес `id` уже занят

#### `PUT /courses/:id` ✏️

Заменяет курс целиком. `id` берётся из адреса, в теле он игнорируется.

Дата изменения (`updatedAt`) становится временем запроса. Чтобы выставить её вручную, передайте в теле `updatedAt` — дату в ISO (`"2026-09-29"` или `"2026-09-29T12:00:00.000Z"`), не позже завтрашнего дня. Панель управления передаёт её, только когда автор поменял дату сам.

- `200 { "course": Course }`
- `400`, `403` — курс чужой, `404`

#### `DELETE /courses/:id` ✏️

- `204` — удалён
- `403` — курс чужой, `404`

#### `POST /courses/:id/review` ✏️

Отправить скрытый курс на проверку: ставит `reviewRequestedAt` и пишет администраторам. Повторный запрос ничего не меняет.

- `200 { "course": Course }`
- `400` — курс уже опубликован; `403` — курс чужой, `404`

#### `DELETE /courses/:id/review` ✏️

Снять курс с проверки. Автор так отзывает заявку. Администратор с чужим курсом — возвращает его на доработку: автору уходит письмо, в него попадает причина из тела.

```json
{ "reason": "Во втором уроке не хватает картинок" }
```

- `200 { "course": Course }`
- `403` — курс чужой, `404`

### Картинки

#### `POST /uploads` ✏️

Загружает картинку для урока или обложки. Файл отправляется телом запроса как есть, без `multipart`:

```
POST /uploads
Authorization: Bearer <token>
Content-Type: image/png

<байты файла>
```

Принимаются `image/jpeg`, `image/png`, `image/webp`, `image/gif`, `image/avif`, до 10 МБ. SVG не принимается: открытый напрямую, он мог бы выполнить скрипт на домене API.

Перед сохранением картинка сжимается в JPEG:

- поворачивается по EXIF;
- уменьшается до 2000 px по длинной стороне, маленькие картинки не увеличиваются;
- прозрачный фон заливается белым;
- сохраняется с качеством 80 (progressive, mozjpeg), метаданные — геолокация, модель камеры — удаляются.

Анимированный GIF сохраняется как есть, иначе от анимации остался бы один кадр.

- `201 { "url": "https://api.courses.aquarium.org.ru/uploads/2026-09/mulx4bdn-a00b426ab09e.jpg" }`
- `400` — файл пустой или повреждён
- `413` — больше 10 МБ
- `415` — неподходящий тип

Файлы лежат в `UPLOADS_DIR/<ГГГГ-ММ>/` и раздаются по адресу `/uploads/…`.

### Администрирование

#### `GET /admin/users` 👑

Пользователи, новые сверху. Параметр `?access=0` оставляет только пользователей с этим уровнем — например, ждущих подтверждения. У каждого — его курсы: `courses: [{ id, title, disabled, reviewRequestedAt, updatedAt }]`.

`200 { "users": [User & { courses }] }`

#### `PATCH /admin/users/:id/access` 👑

```json
{ "access": 1 }
```

- `200 { "user": User }`
- `400` — неизвестный уровень или попытка поменять уровень себе
- `404` — пользователя нет

### Курс

Что принимают `POST` и `PUT /courses` и что проверяется (`services/validateCourse.js`):

| Поле | Тип | Правила |
|---|---|---|
| `id` | строка | Обязательно при создании. Латиница, цифры, дефис; до 64 символов |
| `title` | строка | Обязательно, до 200 |
| `subtitle` | строка | До 500 |
| `accent` | строка | `mint`, `lilac`, `peach`, `sky`, `rose`, `amber`, `teal`, `indigo`, `unity`, `node`, `expo`; по умолчанию `mint` |
| `section` | строка | Обязательно, до 32 |
| `difficulty` | число | Целое от 1 до 5, по умолчанию 1 |
| `disabled` | boolean | Курс закрыт; по умолчанию `true` |
| `level`, `duration` | строка | До 100 |
| `image`, `video`, `github`, `certificate` | строка или `null` | До 500 |
| `chips` | строки | До 12 тегов по 40 символов |
| `author` | объект или `null` | `{ name, email, telegram }` |
| `about` | блоки | Описание курса |
| `pages` | уроки | См. ниже |

Урок в `pages`: `{ slug, title, short, content, … }`. `slug` обязателен, уникален внутри курса, латиница, цифры и дефис, до 64 символов. `title` — до 200, `short` — короткое название для меню, до 100; оба могут быть пустыми. `content` — блоки. Остальные поля урока сохраняются как есть.

Блок — объект с полем `block`: `p`, `h2`, `h3`, `img`, `quote`, `note`, `code`, `ul`, `ol`, `table`, `checklist`, `courses`, `quiz`. Сервер проверяет только тип блока; схема каждого блока описана на сайте, в `src/data/courses.js`.

В ответе к курсу добавляются `ownerId`, `createdAt`, `updatedAt` и `reviewRequestedAt` — когда курс отправили на проверку (`null` — не ждёт), а также `views` и `readers` — сколько раз открывали курс и сколько разных читателей. `Course` — курс со всеми полями. `CourseShort` — без `about`, а у уроков только `slug`, `title` и `short`.

### Ошибки

Ошибка — JSON с текстом для пользователя:

```json
{ "message": "Курс не найден." }
```

Иногда есть поле `status`: `wip` — курс закрыт, `pending` — аккаунт ждёт подтверждения администратора (ответ `403` на действия автора).

| Код | Когда |
|---|---|
| `400` | Неверные данные |
| `401` | Нет токена, он просрочен или неверен — нужно войти заново |
| `403` | Недостаточно прав |
| `404` | Не найдено |
| `409` | Адрес курса занят |
| `413` | Слишком большой запрос: JSON больше 2 МБ, картинка больше 10 МБ |
| `415` | Неподходящий тип картинки |
| `429` | Слишком много попыток входа |
| `500` | Ошибка сервера; подробности — в логе |
| `502` | Не удалось отправить письмо |

## База

Четыре таблицы (`database/schema.sql`):

- `users` — почта, имя, уровень доступа, даты регистрации и последнего входа;
- `codes` — хэши кодов входа, срок и число попыток;
- `courses` — курсы; `chips`, `author`, `about` и `pages` хранятся в JSON-колонках, `user_id` — владелец, `views_count` и `readers_count` — статистика;
- `course_readers` — какие анонимные читатели уже открывали курс.
